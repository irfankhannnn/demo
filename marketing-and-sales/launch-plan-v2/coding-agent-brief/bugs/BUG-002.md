# `billing.js` Uses Stub `incrementSeatsPaid` — Seat Webhook Never Updates DDB

## Epic
ZEE-004 + ZEE-005 / PR-F + PR-H

## Story
ZEE-004-T1 (subscription.updated branch) + ZEE-005-T1 (`subscriptionService.incrementSeatsPaid`)

## Requirement
On `subscription.updated` Razorpay webhook, call `incrementSeatsPaid(tenantId)` from `server/subscriptionService.js` to update the `Subscriptions` table.

## Current State
`server/routes/billing.js:10-13` defines a local stub:

```10:13:server/routes/billing.js
async function incrementSeatsPaid(tenantId, by) {
  logger.info('[subscriptionService stub] incrementSeatsPaid', { tenantId, by });
}
```

`server/subscriptionService.js:28-40` has the real implementation but is **never imported** by `billing.js`. Line 245 calls the local stub.

## Expected State
`billing.js` imports `{ incrementSeatsPaid } from '../subscriptionService.js'` and calls it on seat-add webhook events.

## Gap Analysis
PR-H created `subscriptionService.js` but PR-F's stub was never replaced during merge into `auth_rbac_feature`. Seat purchases via Razorpay do not update `seatsPaid`.

## Impact
- **User:** Pays for extra seat; invite still blocked at old cap.
- **Business:** Revenue collected without service delivery — support burden + refund risk.
- **Technical:** `Subscriptions.seatsPaid` drifts from Razorpay reality.

## Required Changes
1. Remove stub in `billing.js`; import real `incrementSeatsPaid`.
2. Add unit/integration test: mock webhook `subscription.updated` → assert DDB `seatsPaid` incremented.

## Acceptance Criteria
- `subscription.updated` with seat add payload increments `Subscriptions.seatsPaid` by 1.
- `POST /api/subscriptions/check-seat` reflects new cap after webhook.

## Files Likely Impacted
- `server/routes/billing.js`
- `tests/seat-cap.spec.ts`
