# Incomplete P10 Event Instrumentation — Majority of Catalogue Events Not Wired

## Epic
ZEE-003 + ZEE-012 / PR-E + PR-M

## Story
ZEE-003-T4 — Instrument all CRM SPA events from P10 catalogue
ZEE-012-T1 — Event coverage audit

## Requirement
`01-SHARED-CONTRACTS.md §3.4` lists 24+ `AnalyticsEvent` types. P10 requires `trackEvent()` on signup funnel, paywall, seat limit, NPS, feature first-use, etc.

## Current State
`grep trackEvent real-estate-crm-app/src` finds calls in only **5 files**:
- `PhoneLogin.tsx` — `signup_started`
- `RegisterAdmin.tsx` — `agency_registered`
- `RoleSelection.tsx` — `onboarding_role_selected`
- `BuyerDetails.tsx` — `buyer_added` (partial first-use)
- `analytics.ts` — definition

**Missing `trackEvent` calls** (confirmed absent):
- `otp_verified` — not in PhoneLogin OTP handler
- `signup_completed` — not fired client or server on registration complete
- `trial_paywall_shown` / `trial_paywall_clicked` — `PaywallModal.tsx`, `TrialCountdownBanner.tsx` have zero trackEvent
- `nps_response` — `NpsModal.tsx` has zero trackEvent
- `paywall_seat_limit_hit` — only server-side in `subscriptions.js` check-seat
- `subscription_started` — `PaywallModal.tsx` / `razorpay.ts` not instrumented
- `demo_banner_dismissed` — `DemoBanner.tsx` not instrumented

`day-04-event-coverage.csv` documents most events as "deferred" but ZEE-012-T1 marked `[x]` complete.

## Expected State
Every P10 catalogue event has a located `trackEvent()` or `serverTrack()` call with correct properties per spec.

## Gap Analysis
PR-M delivered CSV documenting gaps but did not close them. Components were built without analytics hooks.

## Impact
- **User:** None direct.
- **Business:** Cannot run CRO, funnel analysis, or Day 22 PostHog-based fixes.
- **Technical:** PostHog project will show incomplete funnel.

## Required Changes
1. Add `trackEvent` to each component per P10 mapping table.
2. Add `serverTrack('signup_completed', ...)` in `auth.js` post-registration handler.
3. Update `day-04-event-coverage.csv` — all rows `properties_match=Y`.

## Acceptance Criteria
- CSV audit shows 100% event coverage.
- `tests/analytics.spec.ts` validates key funnel events fire.
