# Seat-Cap Not Enforced at Auth Invite API — Client-Only Check via `check-seat`

> **AUDIT 2026-06-13 — SERVER ENFORCEMENT CONFIRMED; tracked as residual risk.** The billing service (`server/subscriptionService.js` + `/subscriptions/check-seat`) is the authoritative seat gate and returns `402` when over cap; the CRM consumes it before inviting. The invite-creation API in the separate `reality-flow-authentication` service does not re-check the cap server-side, so this remains a **High** residual risk documented in `05-launch-gaps.md` (cross-service enforcement is out of scope for this repo's PR). This PR adds the `paywall_seat_limit_hit` analytics event when the 402 fires.

## Requirement
`01-SHARED-CONTRACTS.md` and `PR-H-seat-cap.md`: seat enforcement at **API layer** in auth invite handler before invite creation. Return HTTP 402 `{ error: 'paywall_seat_limit', ... }`.

## Current State
- `server/routes/auth.js` contains only `POST /post-registration` (Brevo wire-up) — **no invite handler**.
- Seat check implemented as separate endpoint: `POST /api/subscriptions/check-seat` in `subscriptions.js:54-93`.
- `InviteManagement.tsx:178` calls `check-seat` client-side before invite — enforcement is **opt-in via UI**, not server-mandatory on invite API.

`ZEESHAN-tasks.md` notes deviation: "auth.js is empty; invite goes to external Cognito service."

## Expected State
Whatever service creates team invites must enforce seat cap server-side. If invites go through `reality-flow-authentication` microservice, that service must enforce cap — not bypassable by direct API call.

## Gap Analysis
Architecture uses external auth microservice for invites; PR-H spec assumed `server/routes/auth.js` invite handler. Enforcement moved to optional pre-check endpoint — **bypassable** if client skips check or uses API directly.

## Impact
- **User:** None if UI always checks; revenue leak if bypassed.
- **Business:** Team plan agencies could add unlimited members without paying.
- **Technical:** Defense-in-depth missing.

## Required Changes
1. Identify actual invite-creation API (auth microservice route).
2. Add `getSubscription` + seat check before invite creation; return 402.
3. Keep `check-seat` as UX helper but duplicate enforcement at authoritative endpoint.
