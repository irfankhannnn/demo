# Seven Launch DynamoDB Tables Not Defined in CloudFormation

## Epic
FND-002 / INFRA-01 — AWS Infrastructure

## Story
`01-SHARED-CONTRACTS.md §1` — 7 new tables required before coding PRs deploy

## Requirement
Tables: `Grievances`, `AIEmployeeProvisioning`, `WebhookLog`, `TenantApiKeys`, `Subscriptions`, `NPSResponses`, `BetaInvites` with schemas, GSIs, PITR per shared contracts.

## Current State
- Grep of `server/infra/` and repo `*.tf` files: **no references** to these table names.
- Services reference tables via env vars (e.g. `SUBSCRIPTIONS_TABLE`, `GRIEVANCES_TABLE`) with string defaults.
- `pending-tasks/01-infra-setup.md` INFRA-01 lists manual console creation — not done in code.

Evidence: `server/subscriptionService.js:11` → `TABLE_NAME = process.env.SUBSCRIPTIONS_TABLE || 'Subscriptions'`

## Expected State
Either CFN resources in `server/infra/cfn-backend.yaml` (or separate stack) **or** confirmed deployed tables in AWS matching shared-contract schemas.

## Gap Analysis
Code assumes tables exist; infrastructure-as-code does not provision them. Runtime will throw `ResourceNotFoundException` on first API call in any fresh environment.

## Impact
- **User:** Grievance form, billing, NPS, seat checks all fail with 500 errors.
- **Business:** Launch blocked until manual DDB creation.
- **Technical:** No reproducible environment; staging/prod drift.

## Required Changes
1. Add 7 DynamoDB table resources to CFN with GSIs per `01-SHARED-CONTRACTS.md`.
2. Wire table names to Lambda env vars in deployment params.
3. Document in `pending-tasks/01-infra-setup.md` if manual path chosen — mark INFRA-01 status.

## Acceptance Criteria
- `aws dynamodb describe-table` succeeds for all 7 tables in target account.
- Smoke test: POST `/api/grievance` creates row; GET `/api/subscriptions/current` returns data.

## Files Likely Impacted
- `server/infra/cfn-backend.yaml`
- `server/infra/cfn-params.json`
- `pending-tasks/01-infra-setup.md`
