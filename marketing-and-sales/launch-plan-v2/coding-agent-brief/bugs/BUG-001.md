# Billing Webhook Mounted After `express.json()` — HMAC Verification Broken

## Epic
ZEE-004 / PR-F — Razorpay Billing Webhook

## Story
ZEE-004-T1 — `POST /api/billing/webhook` with HMAC-SHA256 signature verify

## Requirement
`00-MASTER-BRIEF.md` and `PR-F-billing-webhook.md` require the billing webhook route to be mounted **before** `express.json()` so Razorpay receives the raw request body for HMAC verification.

## Current State
In `server/server.js`, `express.json()` is registered at line 67, but `billingRoutes` is mounted at line 83 — **after** JSON parsing.

```67:83:server/server.js
app.use(express.json());
app.use(express.urlencoded({ extended: true }));
// ...
// Billing webhook (MUST be before express.json() to preserve raw body for HMAC)
app.use('/api/billing', billingRoutes);
```

`server/routes/billing.js:75` uses `express.raw({ type: 'application/json' })` on the route, but the global `express.json()` middleware has already consumed and parsed the body. `req.body` will be a parsed object, not a Buffer — `rawBody.toString()` and HMAC over `rawBody` will fail or produce incorrect signatures.

## Expected State
Billing router mounted **before** `express.json()`, or a dedicated raw-body middleware applied only to `/api/billing/webhook` at the app level before JSON parsing.

## Gap Analysis
Comment says "MUST be before express.json()" but implementation contradicts the comment. All legitimate Razorpay webhooks will return `401 invalid_signature` in production.

## Impact
- **User:** Subscriptions, AI Employee provisioning, and seat increments never activate from payment events.
- **Business:** Zero revenue attribution; AI Employee concierge never triggers.
- **Technical:** Entire billing webhook path is non-functional.

## Required Changes
1. Move `app.use('/api/billing', billingRoutes)` above `app.use(express.json())` in `server/server.js`.
2. Add integration test: POST webhook with valid HMAC against running server → 200.
3. Verify `cross-tenant-pentest.spec.ts` webhook test still passes.

## Acceptance Criteria
- Valid Razorpay test webhook with correct `x-razorpay-signature` returns 200.
- Invalid signature returns 401.
- Other `/api/*` routes still parse JSON normally.

- `tests/cross-tenant-pentest.spec.ts`
