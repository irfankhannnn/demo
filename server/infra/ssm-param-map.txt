# Maps each Lambda env var name (as the app code reads it via process.env.X,
# and as it appears in SSM under /<env>/realestateflow/server/<KEY>) to the
# CloudFormation parameter that holds its value (as generated fresh into
# cfn-params.json by deploy.sh on every run, from .env.<env>).
#
# Read by sync-ssm-params.sh. NODE_ENV and LOG_LEVEL are deliberately absent
# — they stay as direct Lambda env vars (see cfn-backend.yaml) since they're
# needed before SSM hydration can even run. Every other key ApiLambdaFunction
# or CallRecordingWorkerFunction used to receive directly now goes through
# SSM instead, to stay under Lambda's 4KB env var limit — see
# server/config/ssmBootstrap.js for the runtime side of this.
#
# Deliberately absent: CALL_RECORDING_QUEUE_URL. Its original !Ref target
# (CallRecordingQueue) is a CFN *resource* (the SQS queue), not a Parameter —
# its URL doesn't exist until CloudFormation creates the queue, so it can't
# be pre-synced to SSM before the deploy runs. Stays a direct Lambda env var
# in cfn-backend.yaml (!Ref CallRecordingQueue), same as before this migration.
#
# Format: ENV_VAR_NAME=CfnParameterName
