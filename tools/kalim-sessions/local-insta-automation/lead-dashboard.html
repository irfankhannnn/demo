How it works

The rules this app follows, so nothing it does is a surprise.

What is connected right now

  • SQLite is the source of truth. Everything lives in db/lead-desk.db. The Excel workbook was imported once by scripts/migrate_to_sqlite.py and is no longer read. Open the database with any SQLite browser if you want the raw rows.
  • The Instagram handle is the key. Every import matches on it, so a re-run updates a conversation instead of duplicating it, and messages de-duplicate on handle, date, time and text.
  • A blank never clears a known value. An import with a shorter thread leaves the budget already on file alone. Typing a blank into a field in this app does clear it, because you meant it — and the old value is kept in the history.
  • Every change is recorded. Field edits, reel links, assignments and status moves all append to the changelog with the old and the new value. Nothing is overwritten silently.
  • A pasted screenshot is read, not trusted. Add a DM sends the picture to the AI, which reads the handle off the thread header — the one thing in the flow with no ground truth behind it. So the read shows you what it got and saves nothing; only Add writes, with whatever handle you confirmed. A batch you discard leaves the database untouched.
  • A drafted reply is a draft. The model is given the real matching properties and told explicitly when there are none, so it will not invent a listing or a price. Read it before you send it. Nothing is ever sent for you.
  • You are never shown sample inventory. If no property backend is connected, the inventory lane says so and stays empty. The sample file in config/ is used only when ALLOW_SAMPLE_INVENTORY is set in .env, so an invented flat cannot reach a real conversation by accident.
  • An empty property search is not proof of nothing. The semantic search returns an empty list rather than an error when its vector index was never built, so the app falls through to a filter search, and always names which one answered.
  • Reel links are context, not decoration. Paste the reels a lead shared and tag one with a property id. The draft and the answer are then written about the listing the lead actually saw, and the links travel with the sourcing assignment.
  • Answers come only from the property record. Ask about a property and the model may use nothing but the fields inventory returned. Whatever it does not know is listed as unknown rather than guessed.
  • Sourcing status is yours. An import carries it forward untouched. Marking a task done will not be undone by processing another DM export.
  • Nothing leaves this laptop except the model call. Credentials live in .env and never reach the browser. The page talks only to 127.0.0.1.
